Authorization

The service registry API uses OAuth2 for authorization and expects self-contained JWTs from Maskinporten. The JWT token requests to Maskinporten are expected to contain x5c for the Norwegian business certificate (SEIDv1 or SEIDv2) the token request was signed with.

  • Maskinporten (external link)

eFormidling creates OAuth clients in Maskinporten as part of the onboarding process:

  • The Client ID is MOVE_IP_<orgnumber>

  • One or more of the following scopes are granted to the client:

    • eformidling:dpo (eFormidlings meldingstjeneste)

    • eformidling:dpe (eInnsyns meldingstjeneste)

    • eformidling:dpi (Digital Post til Innbyggere)

    • eformidling:dpf (KS SvarUt og SvarInn)

    • eformidling:dpv (Altinn Digital Post)

    • eformidling:dph (Digital post til helse)

/identifier, /info, /virksert and /sastoken require at least one of these scopes. Tokens without one of them get 403. Some lookups also require a specific scope:

  • Service records for persons (DPI) require eformidling:dpi.

  • Service records for healthcare receivers (DPH) require eformidling:dph.

  • /sastoken requires eformidling:dpe.

  • /virksert returns the certificate for DPO or DPE, depending on whether the token has eformidling:dpo or eformidling:dpe. The identifier must be a Norwegian organization number, either bare or as 0192:<orgnr>, with a valid check digit. Other identifiers get 400.

The older scopes move/dpo.read, move/dpe.read, move/dpi.read, move/dpf.read and move/dpv.read are still accepted in place of the corresponding eformidling: scope, because integrasjonspunkt versions from before March 2026 request them. New clients should use the eformidling: scopes.
